# 功能规范: 修复行情 API 行为漂移

**功能分支**: `006-fix-api-invest`  
**创建日期**: 2025-12-22  
**状态**: 草稿  
**输入**: 用户描述: "fix the issue mentioned in api_invest.txt"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 行情查询可靠返回（优先级: P1）

作为 API 使用者，我希望请求股票报价或 K 线数据时能稳定得到正确响应或明确错误，这样我的上游页面不会因为不一致的失败而中断。

**为什么是此优先级**: 这是外部用户最直接的体验，任何不稳定都会导致核心功能不可用。

**独立测试**: 通过对有效股票代码发起报价与 K 线请求，验证成功响应与必要字段完整即可交付主要价值。

**验收场景**:

1. **Given** 有效股票代码且参数完整, **When** 用户请求报价或 K 线数据, **Then** 系统返回成功结果且响应结构符合约定
2. **Given** 有效股票代码但请求参数缺失, **When** 用户请求报价或 K 线数据, **Then** 系统返回一致且可理解的错误结果

---

### 用户故事 2 - 错误信息可区分（优先级: P2）

作为 API 使用者，我希望系统能区分参数错误、权限问题与上游失败，以便我能快速定位问题并给用户提示。

**为什么是此优先级**: 错误类型可区分能显著降低排查成本并提升恢复速度。

**独立测试**: 通过构造无效股票代码、缺失必填参数或上游错误的请求，验证错误类型与响应一致即可。

**验收场景**:

1. **Given** 无效股票代码, **When** 用户请求报价或 K 线数据, **Then** 系统返回参数错误类结果
2. **Given** 上游数据获取失败, **When** 用户请求报价或 K 线数据, **Then** 系统返回上游失败类结果

---

### 用户故事 3 - 默认行为可预测（优先级: P3）

作为 API 使用者，我希望在未指定数据来源时系统有明确的默认行为，这样我无需额外配置也能获得结果。

**为什么是此优先级**: 默认行为一致可减少调用摩擦，但不影响核心可用性，因此优先级较低。

**独立测试**: 在不提供来源参数的情况下发起请求，验证结果与默认行为一致即可。

**验收场景**:

1. **Given** 未指定数据来源, **When** 用户请求报价或 K 线数据, **Then** 系统采用默认来源并返回结果

---

### 边界情况

- 当请求缺少必要的 URL 信息或格式不合法时，系统如何返回可理解的错误？
- 当数据来源参数为空或未知时，系统是否统一返回可预测的错误或回退行为？
- 当上游服务返回异常结构时，系统是否仍能给出一致错误类型？

### 范围与非目标

- 仅覆盖报价与 K 线查询的请求与响应行为一致性。
- 不新增或更换数据来源类型，仅确保现有行为一致可预测。
- 不涉及前端界面或权限体系的变更。

## 需求 *(必填)*

### 功能性需求

- **FR-001**: 系统 MUST 在报价与 K 线请求中解析并使用数据来源参数。
- **FR-002**: 系统 MUST 在未提供数据来源时采用明确的默认来源。
- **FR-003**: 系统 MUST 对有效股票代码返回成功结果且响应结构稳定一致。
- **FR-004**: 系统 MUST 将参数错误、权限问题与上游失败映射为可区分的错误结果。
- **FR-005**: 系统 MUST 在请求缺少必要 URL 信息时返回可理解且一致的错误结果。

### 非功能需求 *(必填)*

- **NFR-001**: 功能上线时 MUST 同步更新相关规范或文档以反映当前行为。
- **NFR-002**: MUST 使用 Sentry spans 与 logs 定义结构化日志与追踪。
- **NFR-003**: MUST 使用全面的单元测试覆盖所有新增或修改逻辑。

### 关键实体 *(当功能涉及数据时填写)*

- **股票代码**: 用户请求的标识，决定目标股票。
- **数据来源**: 用户可选参数，决定数据提供方，缺省时使用默认值。
- **行情响应**: 报价或 K 线返回的结果或错误，需包含可区分的类型信息。

### 假设

- 默认数据来源为系统当前既定的默认值。
- 报价与 K 线接口对错误类型的分类规则已确定并可复用。

### 依赖

- 当前系统已有可用的数据来源配置与错误分类规则。

## 成功标准 *(必填)*

### 可量化结果

- **SC-001**: 90% 以上的有效行情请求在一次调用内返回成功结果。
- **SC-002**: 100% 的参数错误请求返回可区分的错误类型且不被误报为系统错误。
- **SC-003**: 95% 的调用者在未指定数据来源时仍能完成一次成功请求。
- **SC-004**: 与行情接口错误类型相关的支持问题在上线后 4 周内减少 50%。
